# ذكاء جودة البيانات والتنظيف والتحقّق — Data Quality Intelligence

المرحلة ٣ من **Migration Intelligence Platform**. المشكلة ليست نقل
البيانات، بل أن بيانات العميل غالبًا سيّئة. لا يجوز ترحيل بيانات سيّئة.

> **Garbage In = Garbage Out.** الهدف: تحويل البيانات السيّئة إلى بيانات
> موثوقة. **بلا ترحيل، بلا تحويل، بلا تعديل للأصل، بلا تطبيق تلقائي.**

## القرار المعماري (أمين)

المرحلتان ١ و٢ اشتغلتا على **البنية** (Schema). جودة البيانات تحتاج
**الصفوف الفعلية**. لذلك:
- Phase 3 تشتغل على **بيانات المصادر المرفوعة (CSV/JSON)**.
- تُحلَّل في الذاكرة، وتُحفَظ **المشتقّات فقط** (مقاييس + مشاكل + تصحيحات
  مقترَحة) — **لا تُخزَّن الصفوف الخام** (خصوصية).
- كل تصحيح يُسجَّل في **نسخة عمل** (changeset): قيمة قديمة → جديدة، لا
  يُطبَّق على الأصل إلا بعد اعتماد المدير — قابل للتدقيق والتراجع.

## كشف التكرار (المعنى لا الحرف)

«Mohamed Ali / محمد علي / Mohamad Aly» قد يكونوا نفس الشخص. المحرّك يجمع:
- **تطبيع** عربي/لاتيني (تشكيل، همزات، تطويل، رموز).
- **Levenshtein** + تشابه رمزي (يتحمّل اختلاف ترتيب الكلمات).
- **بصمة صوتية** (Aly ≈ Ali) مع **Blocking** لتفادي O(n²).
- إجراء مقترَح: دمج / إبقاء / أرشفة / مراجعة يدوية — **لا حذف تلقائي**.

## أبعاد الجودة

لكل حقل: اكتمال · صلاحية · تفرّد · اتساق · Trust Score. ثم درجة جودة
عامة /١٠٠. القيم غير الصالحة تُرصَد بنوعها (بريد/هاتف/تاريخ/عملة/دولة/
تعداد/منطقي) مع سبب الخطأ وطريقة التصحيح.

## السلامة المرجعية وقواعد العمل

يستنتج روابط FK من الأسماء عبر المجموعات، ويكتشف: سجلّات يتيمة (FK يشير
لسجلّ غير موجود)، مراجع ناقصة، وتناقضات منطقية (حالة «مدفوع» لكن المبلغ
فارغ). فاتورة بلا عميل، طلب بلا منتج... تُعرَض لا تُهمَل.

## المراجعة البشرية والاعتماد

- أي عنصر بثقة **أقل من ٩٥٪** يدخل Review Queue ولا يُطبَّق تلقائيًا.
- Director/Admin: Approve / Reject / Ignore / اعتماد عالي الثقة دفعةً.
- اعتماد التشغيلة مشروط بحسم كل التصحيحات منخفضة الثقة.
- كل حدث في `data_quality_versions` (تاريخ + تراجع).

## Cleaning Blueprint

بعد التحليل: تحليل + أبعاد + تكرار + مشاكل + تصحيحات (نسخة عمل) + قواعد +
درجة جودة + **تحديث الجاهزية المتوقّع**. هو المرجع الرسمي لمرحلة التحويل.

## التكامل مع الذاكرة المؤسسية

قواعد التنظيف المعتمَدة تُرقَّى كمرشّح خبرة مؤسسية (حاجز مراجعة المدير).
فإذا تكرّر نفس الخطأ مستقبلًا، يُقترَح الحل تلقائيًا.

## الجاهزية للمرحلة ٤ (Intelligent Transformation & Migration Rules Engine)

المرحلة ٣ تُنتج **بيانات موثوقة + Cleaning Blueprint** (تكرار محسوم،
قيم موحّدة، سلامة مرجعية مضمونة) + ترفع Migration Readiness. ده بالظبط
مدخل المرحلة ٤: التحويل الفعلي وقواعد الترحيل تعمل على بيانات نظيفة
مُعتمَدة، لا خام. **جاهز للانتقال للمرحلة ٤.**
