# استيراد المعرفة — المرحلة الخامسة، الجزء الثاني

## معمارية المعالجة

```
رفع الملف
   ↓
scanFile (الاسم + الحجم)        ← رفض فوري قبل التسجيل
   ↓
knowledge_sources               ← الصفّ يُنشأ
   ↓
routeIngest                     ← فيه عامل حيّ؟
   ├── لأ ──→ معالجة مباشرة في Next.js (المسار القائم)
   └── أيوه ─→ الطابور
                 ↓
        عامل المجموعة (٥ أنواع)
                 ↓
        قراءة من المخزن → scanFile بالبصمة
                 ↓
        ┌────────┴────────┐
        │                 │
    أرشيف؟           ملف عادي
        │                 │
   extractZip        استخراج → تقطيع → تصنيف
        │                 │
   مصادر فرعية ──────────┘
                 ↓
        recordBulkCreation      ← إصدارات + خط زمني + حدث
```

### عن OCR — توضيح مهم

**مافيش Tesseract، ومش محتاجين.**

PDF والصور والمستندات الممسوحة بتروح لـ`ai_native` في `file-types.ts`،
يعني Gemini بيقراها **بصريًا** ويستخرج نصّها. ده OCR حقيقي بجودة أعلى
من المحرّكات التقليدية، وبلا أي اعتماد أصلي يثقّل صورة Railway.

إضافة Tesseract كانت هتضيف مئات الميجابايتات لقدرة **موجودة أصلًا**.

## المراجعة الأمنية

### ما هذا وما ليس هذا

**ده مش مضاد فيروسات.** الفحص بالتوقيعات محتاج محرّكًا (ClamAV أو خدمة
خارجية)، وادّعاء وجوده وهو غير موجود **أخطر من غيابه** — لأنه بيدّي
طمأنينة كاذبة.

اللي اتبنى **حواجز بنيوية** بتمنع فئات هجوم حقيقية، وكلها قابلة
للتنفيذ بلا أي اعتماد خارجي.

### الحواجز

| الهجوم | الحاجز | الاختبار |
|---|---|---|
| **امتداد كاذب** — `invoice.pdf` وجوّه `MZ` | مقارنة البصمة بالامتداد | ✅ |
| **تنفيذي بالاسم** — `.exe` `.dll` `.sh` `.ps1`… (٣٠ امتداد) | حظر بالاسم | ✅ |
| **امتداد مزدوج** — `invoice.pdf.scr` | كشف النمط | ✅ |
| **قنبلة ضغط** — ٤٢ كيلو تفكّ لبيتابايت | نسبة ٢٠٠:١ | ✅ |
| **انزلاق المسار** — `../../etc/passwd` | فحص المسار الخام | ✅ |
| **الترميز المزدوج** — `..%2f..` | فحص قبل التطبيع | ✅ |
| **البايت الصفري** — `file\0.txt` | رفض | ✅ |
| **الإغراق بالعدد** — مليون ملف في ZIP | سقف ٥٠٠ | ✅ |
| **الحجم** | ١٠٠ ميجا للملف · ٥٠٠ للمفكوك | ✅ |

### قرارات تصميمية

**الفحص قبل التسجيل لا بعده.** ملف مرفوض مايجوزش يدخل الجدول أصلًا،
وإلا بقى صفًّا معلّقًا يحتاج تنظيفًا.

**حاجزان مكمّلان:** الأول عند الرفع (الاسم والحجم — سريع وبلا قراءة)،
والثاني في العامل (البصمة — بيمسك التمويه لما المحتوى يتقرا).

**ملف واحد خبيث لا يُسقط الأرشيف.** يُستبعَد ويكمّل الباقي — نفس مبدأ
«فشل ملف واحد لا يوقف البقية» في المواصفة. لكن **قنبلة الضغط تُسقط
الأرشيف كله**: الخطر في المجموع لا في مُدخل بعينه.

**النسبة تُحسب على الأرشيف كله.** ملف نصّي صغير بيتضغط بنسبة عالية جدًا
وهو بريء تمامًا؛ الحساب على المجموع بيوازن.

**الفحص على المسار الخام قبل أي تطبيع.** التطبيع نفسه ممكن يخفي الهجوم
(`..%2f..` بيتفكّ لـ`../..`).

### ثغرات معلومة — بصراحة

| البند | الحالة |
|---|---|
| فحص بالتوقيعات (فيروسات معروفة) | ❌ محتاج محرّكًا خارجيًا |
| ماكرو Office (VBA) | ❌ غير مفحوص |
| JavaScript المضمَّن في PDF | ❌ غير مفحوص |
| RAR · 7z | ❌ غير مفكوك — يُحفظ كمرجع |
| ZIP داخل ZIP | ⚠️ مستوى واحد فقط |
