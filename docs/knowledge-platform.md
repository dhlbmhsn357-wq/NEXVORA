# منصة المعرفة المؤسسية — المرحلة الخامسة، الجزءان السابع والثامن

اللمسة الأخيرة: تحويل مركز المعرفة إلى **نظام تشغيل معرفي مؤسسي**
بحوكمة وجودة وأمان وتصدير وتشغيل موحّد.

## المبدأ الحاكم: البناء فوق الموجود

المسح أثبت أن **البنية التحتية كلها موجودة**: كل جداول knowledge_*،
repository/versioning/quality/monitoring/memory/search/security، طبقة
المهام الموحّدة، محرك الإشعارات، صحة الطابور/العمّال/الذكاء، backup
scripts، brain-v2 review stack، graph viewer. فالبناء ركّز على الطبقة
الحاكمة الناقصة فقط.

| موجود ومُعاد استخدامه | الجديد في الجزأين 7+8 |
|---|---|
| `quality.ts` (٥ أبعاد) | تقرير QA موحّد مخزَّن |
| `security.ts` (فحص ملفات) | كشف PII وإخفاؤه على المحتوى |
| `collectMonitoring` | ملخّص الحوكمة في اللوحة |
| صحة الطابور/الذكاء | مركز عمليات موحّد |
| `createTaskFromSource` | جسر المعرفة → مهام |
| محرك الإشعارات | مرشّحو إشعارات المعرفة |
| backup scripts | حزمة معرفة (تصدير/استيراد/نسخ) |

## الجزء الثامن — الحوكمة والجودة والأمان والتشغيل

### الحوكمة — دورة حياة المعرفة

`governance/retention.ts` (نقي): سياسات احتفاظ/أرشفة/حذف بشروط (عمر،
خمول، ثقة). **التقييم مقترَح لا منفَّذ** افتراضيًا — الحذف قرار خطير
يستحق موافقة، والحذف نفسه **ناعم** (تحويل حالة لا مسح) للحفاظ على
التدقيق والتراجع. الأخطر يفوز عند تعارض سياستين.

### الجودة الموحّدة — تقرير لا مجرد درجة

`qa/qa-model.ts` بياخد جودة `computeQuality` القائمة + يضيف فحوصات
(تعارضات، تكرار، فجوات، PII) في **تقرير موحّد** بمشاكل مصنّفة قابلة
للفعل. العقوبة موزونة بالشدّة ومتشبّعة (أقصى ٤٠ نقطة) — تعارض حرج يخصم
أكتر من عشر ملاحظات صغيرة.

### الأمان — كشف PII وإخفاؤه

`security/pii.ts` (نقي): كشف بالأنماط للبريد والهواتف والبطاقات (Luhn)
وIBAN والأرقام القومية ومفاتيح API وعناوين IP. **كشف بالأنماط لا NER**
— بنمسك القابل للتعرّف حتميًا، ومابندّعيش مسك الأسماء الحرة. يُستخدم في
تقرير الجودة (تنبيه) وعند التصدير (إخفاء اختياري).

### التصدير/الاستيراد — حزمة المعرفة

`package/package-model.ts` (نقي): حزمة JSON قابلة للنقل تحمل الكائنات
وعلاقاتها وبياناتها الوصفية. **وحدة التصدير والنسخ الاحتياطي والاستيراد
معًا**. الاستيراد **يعيد ربط العلاقات**: المعرّفات الأصلية تُرمَّز
لجديدة والعلاقات تُبنى فوقها، فالشبكة تُحفَظ. الاستيراد إضافي لا
استبدالي.

### مركز العمليات الموحّد

`ops/operations-center.ts`: يجمّع صحة الطابور والعمّال (`queue/health`)
+ المعرفة + الذكاء الاصطناعي في **نظرة واحدة** بمستوى صحة كلي. أي مصدر
يفشل يرجع «غير متاح» بدل ما يُسقط اللوحة.

## الجزء السابع — طبقة عمل المعرفة (توصيل عالي القيمة)

الـ UI الكامل بنمط Notion (٩ عروض) غير متناسب وأغلبه عرضي؛ **طبقة
الخدمات جاهزة** له، والمبني هنا التوصيل عالي القيمة:

- **جسر المعرفة → مهام** (`knowledge-tasks.ts`): الفجوات عالية الأولوية
  والرؤى الحرجة تتحوّل لمهام موكَلة عبر `createTaskFromSource`
  الـ idempotent. لا إنشاء عشوائي — الحرج فقط.
- **إشعارات المعرفة**: مرشّحون جدد في `reconcile-service` للرؤى الحرجة
  والتعارضات المفتوحة والفجوات — مجمّعون لكل مشروع.

الموجود بالفعل ويغطّي باقي مواصفة Part 7: Timeline (`timeline-service`
+ `repository.listTimeline`)، Graph Viewer (`knowledge-graph-panel`)،
Version Center (`listVersions` + `diffVersions`)، Review/Approval/
Comments (brain-v2 + collaboration)، Search الدلالي (`memory-service`)،
Analytics (`monitoring`)، RBAC (`rbac.ts`).

## الأمان — مراجعة

| الحاجز | الحالة |
|---|---|
| RLS على كل جداول المعرفة | ✅ (قراءة للمصادَقين، كتابة للخدمة) |
| فحص الملفات المرفوعة | ✅ (`security.ts`: بصمات، zip-bomb، مسارات) |
| كشف PII على المحتوى | ✅ جديد (`pii.ts`) |
| إخفاء PII عند التصدير | ✅ اختياري |
| التحقق من الصلاحية في كل إجراء | ✅ (`requireRole`) |
| حذف ناعم لا صلب | ✅ (تحويل حالة، تدقيق محفوظ) |
| Audit trail | ✅ (`knowledge_timeline` + `platform_events`) |

**التوافق المستقبلي (GDPR/SOC2/ISO 27001):** التصميم جاهز — PII قابل
للكشف والإخفاء، سياسات احتفاظ/حذف موجودة، Audit trail كامل، RBAC
مطبَّق. **بلا ربط إلزامي الآن** كما طُلب.
