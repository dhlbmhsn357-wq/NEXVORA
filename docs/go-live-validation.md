# مركز التحقّق وقبول الأعمال وشهادة الإطلاق — Go Live Validation Center

المرحلة ٧ من **Migration Intelligence Platform** (الختامية لمشروع الترحيل).

> **Migration is NOT Finished Until Business Confirms Success.** نجاح الترحيل
> لا يعني وصول البيانات فقط — بل أن العمل (المبيعات/المحاسبة/المخزون/الفروع)
> يعمل صحيحًا وأن العميل اعتمد النظام رسميًا. خط الدفاع الأخير قبل الإغلاق.

## البناء فوق المراحل ١-٦ (لا إعادة تنفيذ)

| يستهلك | من |
|---|---|
| نتائج التنفيذ (أعداد الإنتاج، النسخ الاحتياطية، التراجع) | المرحلة ٦ (0088) |
| أعداد المصدر + إشارات الجودة | المحاكاة المعتمَدة (0087) |
| الإشعارات / RBAC / الطابور (صحة العمّال) | `lib/notifications` · `lib/auth/rbac` · 0073 |

## المعمار — `lib/go-live/`

**نواة نقية حتمية:** `verification-types` · `verification-engine`
(تطابق البيانات + تحقّق تجاري + سيناريوهات وظيفية + قوائم الأقسام) ·
`health-check` · `kpi-validation` · `go-live-checklist` (٩ بنود + الدرجة
النهائية) · `certificate` · `lessons-learned`.

**خدمات:** `verification-service` (يبني التقرير الحتمي + يعيد حساب الدرجات) ·
`acceptance-service` (اعتماد الأقسام/الفروع + UAT + المشكلات) ·
`certificate-service` (إصدار الشهادة المشروط + ترقية الدروس) ·
`ai-verification-service` (استشاري مستند) · `org-memory-integration` ·
`dashboard` · `notify`.

## خطوط التحقّق

- **Data Verification** — Source ↔ Production لكل كيان (عملاء/موظفون/فواتير/
  مخازن/فروع/مرفقات/صلاحيات...): تطابق الأعداد أو فرق يستحق التحقيق.
- **Business Verification** — المبيعات/الفواتير/المخزون/الحسابات/العلاقات/
  التقارير/الصلاحيات (مشتقّ من إشارات المراحل ٥/٦) + Workflow/Approval عبر UAT.
- **Functional Verification** — سيناريوهات حقيقية (إنشاء عميل/فاتورة، بيع/
  إرجاع، استلام دفعة، تحويل مخزون، اعتماد طلب، إنشاء تقرير) تُختبَر في UAT.
- **Health Check** — قاعدة/خدمات/تخزين/أداء/فهارس/طابور/عمّال/كاش + درجة.
- **KPI Validation** — الإيرادات/المخزون/الطلبات/العملاء/الموظفون/الأرباح
  قبل↔بعد: محفوظ/متحسّن/متدهور/مفقود.
- **AI Verification** — طبقة استشارية تكشف السلوك المفقود/غير المتوقّع والمشاكل
  الخفية، **مستندة للتقرير فقط**.

## قبول الأعمال (Business Acceptance Workflow)

- **اعتماد الأقسام** — Sales/Accounting/Inventory/HR/CRM/Warehouse/Management،
  كل قسم يعتمد بياناته ووظائفه مستقلًّا (Checklist لكل قسم).
- **اعتماد الفروع** — لكل فرع (مثل الامتياز بـ11 فرعًا) اعتماد مستقلّ.
- **UAT Center** — لكل مسؤول: Approve/Reject/Comment/Report Issue. فشل UAT
  يفتح مشكلة تلقائيًا.
- كل اعتماد يُسجَّل مع هوية المعتمِد ودوره (**Auditable**)، ويُعيد حساب الدرجات فورًا.

## الدرجة النهائية + الشهادة

- **Verification Score** (تقني) · **Business Acceptance Score** (تجاري) ·
  **Final Migration Score** (موزون).
- **Go Live Checklist** (٩): اكتمال الترحيل · التحقّق · اعتماد الأقسام ·
  اعتماد الفروع · الأداء · الصحة · التراجع مؤرشف · النسخ محفوظة · التوثيق.
- **Go Live Certificate** — لا تُصدَر إلا باكتمال كل البنود الحاجزة وإغلاق كل
  المشكلات. تتضمّن المشروع/الإصدار/الدرجات/الحالة/المعتمِدين، وتُغلق المشروع.

## الصلاحيات

Director: اعتماد الإطلاق (الشهادة) · Admin: إدارة التحقّق · Supervisor:
مراجعة/اعتماد أقسام وفروع وUAT · Executor: لا اعتماد. كل اعتماد Auditable.

> **ملاحظة أدوار:** الأدوار المؤسسية (Department/Branch Manager) تُخدَّم عبر
> تدرّج VELORA (owner/admin/supervisor) مع تسجيل الدور الفعلي في كل صفّ اعتماد.

## الجاهزية للمرحلة ٨ (Hypercare, Monitoring & Continuous Optimization)

المرحلة ٧ تُنتج **اعتمادًا رسميًا موثّقًا** (شهادة + درجات + دروس مؤسسية).
هذا مدخل ما بعد الإطلاق: Phase 8 تراقب النظام الحيّ (Hypercare) وتُحسّنه
باستمرار. **جاهز للانتقال للمرحلة ٨.**
