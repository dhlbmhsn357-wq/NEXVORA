# منصّة الذاكرة المؤسسية — Organizational Memory Platform

الطبقة الثالثة من المعرفة: تحويل VELORA من منصة تعتمد على معرفة المشروع
والمجال، إلى منصة تتعلّم من مشاريعها الحقيقية وتبني خبرة مؤسسية تراكمية.

## تسلسل المعرفة الثلاثي

```
١. Project Knowledge    — معرفة المشروع الحالي (Discovery/اجتماعات/ملفات)
٢. Domain Knowledge     — معايير قياسية يضيفها المدير (حزم المجال)
٣. Organizational Memory — خبرة مستخلَصة من المشاريع السابقة بعد اعتماد المدير
```

**طبقة مستقلة فوق Knowledge Hub وDomain Library لا بديلة عنهما.** كل
المراحل اللاحقة (Brain، PRD، Recommendations، Engineering QA...) تدمج
الطبقات الثلاث معًا.

## المعمار

`lib/organizational-memory/` — موديول مستقل:

| المحرّك | الملف |

| اكتشاف الأنماط (نجاح/فشل/مضادّ) | `pattern-discovery.ts` |

| اللوحة | `dashboard.ts` |

## سير ترقية الخبرة (Experience Promotion Workflow)

```
المدير يضغط «اعتماد المشروع كمصدر خبرة» (لا تلقائي)
        ↓
extractProjectExperience: يجمع المعرفة المهيكلة للمشروع
        ↓
sanitizeExperience: يُخفي PII ويجرّد أسماء العملاء (حاجز إلزامي)
        ↓
org_experience_candidates (pending) ← لا يدخلون المكتبة مباشرة
        ↓
مراجعة المدير: قبول / رفض / تعديل / دمج / أرشفة
        ↓ (عند القبول + حاجز أمني أخير)
org_experiences → مكتبة الخبرات المؤسسية → متاحة لكل المشاريع
```

## اكتشاف الأنماط (Pattern Discovery)

`discoverPatterns` (نقي): التكرار عبر المشاريع هو الإشارة. شيء ظهر مرة =
حالة؛ في مشروعين+ = نمط. الإشارة تصنّف:
- غالبية نجاح → **نمط نجاح** (أو **أفضل ممارسة** لو تكرّر في ٥ مشاريع+)
- غالبية فشل → **نمط فشل**
- نجاح وفشل لنفس المفتاح → **نمط مضادّ**

## استخلاص الدروس المستفادة

`buildLessonsReport` (نقي): ما نجح / ما فشل / ما تحسّن → توصيات قابلة
للفعل («كرّر: …» / «تجنّب: …»).

## الأمان والخصوصية

**حاجز إلزامي بين المعرفة الخاصة والمكتبة العامة:**
- `sanitizeExperience` يُخفي PII (يعيد استخدام الجزء الثامن) + يجرّد
  أسماء العميل/المشروع لـ«[الجهة]».
- حاجز أخير في `approveCandidate`: لو تبقّى PII مكشوف، يُرفَض الاعتماد.
- **لا تُنقَل بيانات عملاء ولا أسرار** — فقط معرفة عامة قابلة لإعادة
  الاستخدام.

## الثقة والتحسين المستمر

- `computeConfidence`: تنمو مع عدد المشاريع المُثبِتة؛ المراجعة البشرية
  ترفع الأرضية.
- `usageAdjustment`: استُخدمت في ٣٠ مشروعًا وأثبتت نجاحها → زيادة تلقائية؛
  ثبت ضعفها بعد استخدام كافٍ → اقتراح التقاعد.

## الإصدارات والتراجع

كل خبرة لها إصدار وتاريخ. `reviseExperience` يكتب إصدارًا جديدًا (لا
استبدال صامت)؛ `rollbackExperience` يتراجع بكتابة القديم كإصدار جديد —
التاريخ محفوظ دائمًا.

## التكامل مع محرّك الدمج

`buildFusedContext` (طبقة الدمج) بقى يقرأ **ثلاث طبقات**: معرفة المشروع
+ معرفة المجال + الذاكرة المؤسسية. وزن `org_memory` = ٧٨ (بين معيار
المجال ٨٠ وأفضل ممارسة ٧٥). التعارضات تُعرَض لا تُستبدَل.

## التفسير (Explainability)

كل خبرة تحمل `source_project_ids` + الثقة + المجال. المكتبة تعرض «من N
مشروع · ثقة X٪ · استُخدمت M مرة» — فأي استخدام لخبرة مفسَّر.

## الصلاحيات

| الدور | القدرة |
|---|---|
| **Director** (owner) | كامل الصلاحيات (ترقية، اعتماد، إدارة) |
| **Admin** | يقترح الترقية |
| **Supervisor** | قراءة فقط |
| **Executor** (member) | لا يرى الذاكرة المؤسسية |

## التأثير على مراحل المنصة

`buildFusedContext` مصدر موحّد للطبقات الثلاث. المراحل اللاحقة تقرأ منه:
- **Project Brain**: أعمق — يستفيد من خبرة كل المشاريع السابقة
- **PRD**: مستوى Enterprise حتى للمشاريع المعقّدة
- **Smart Recommendations**: أقوى بأنماط النجاح والفشل المُثبَتة
- **Engineering QA**: يتعلّم من الأخطاء المتكرّرة السابقة

## ثغرات معلومة — بصراحة

| البند | الحالة |
|---|---|
| التعلّم التزايدي (Delta بعد تعديل مشروع معتمَد) | ⚠️ الاستخلاص الكامل جاهز؛ Delta-only خطوة تالية |
| البحث الدلالي في المكتبة | ⚠️ بحث نصّي جاهز؛ الدلالي يُبنى فوق `memory-service` |
| توصيل الطبقة الثالثة **داخل** كل مولّد downstream | ⚠️ `buildFusedContext` يقرأ الثلاثة؛ استدعاؤه من كل مولّد خطوة تالية |
| اكتشاف الأنماط بالذكاء الاصطناعي فوق الحتمي | ⚠️ الحتمي جاهز ومختبَر؛ التهذيب بالذكاء إضافة |

كلها **قدرات تُبنى فوق الأساس المكتمل**، لا حواجز فيه.
